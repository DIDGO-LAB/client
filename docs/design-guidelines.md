# Didgo Client Design Guidelines

이 문서는 `client` 프로젝트의 UI 수정 작업을 일관되게 진행하기 위한 기준이다. 목표는 화면을 예쁘게 만드는 것보다, 현재 사용자 흐름을 해치지 않으면서 같은 톤과 규칙으로 화면을 정리하는 것이다.

## 1. Scope

현재 디자인 작업의 대상은 아래 화면으로 한정한다.

- 시작/회원가입 플로우
- 로그인
- 홈
- 훈련 선택, 훈련 진행, 훈련 결과
- 훈련 이력
- 내 정보
- 공통 레이아웃 요소 (`Sidebar`, `PageHeader`, 상태 화면)

현재 라우팅 기준으로 실제 사용 중인 화면은 아래 파일들이다.

- `src/App.jsx`
- `src/components/layout/Sidebar.jsx`
- `src/pages/Login.jsx`
- `src/pages/Mainpage.jsx`
- `src/pages/MyPage.jsx`
- `src/pages/training/TrainingPages.jsx`
- `src/components/intro/*`

아래 코드는 현재 라우팅에서 직접 사용하지 않는 레거시 후보로 보고, 디자인 수정의 기준 파일로 삼지 않는다.

- `src/pages/TrainMain.jsx`
- `src/pages/SocialTraining.jsx`
- `src/components/training/social/*`

## 2. Product Tone

이 서비스는 마케팅 사이트가 아니라 훈련용 작업 도구다. 따라서 화면은 아래 방향을 유지한다.

- 조용하고 안정적인 톤
- 과한 장식보다 명확한 정보 구조
- 큰 버튼, 분명한 상태 구분, 쉬운 스캔
- 훈련 상황에 집중할 수 있는 낮은 시각적 피로도
- 사용자에게 설명문을 길게 읽게 하기보다 바로 행동하게 만드는 구조

피해야 할 방향:

- 랜딩페이지식 히어로 구성
- 의미 없는 카드 중첩
- 과한 그라디언트, 오브, 장식용 배경 효과
- 한 화면 안에 너무 많은 강조색
- 버튼/텍스트 크기가 화면마다 들쭉날쭉한 구성

## 3. Layout Principles

이 프로젝트는 현재 `1920x1080` 고정 캔버스를 축소하는 방식으로 동작한다. 따라서 레이아웃 수정은 반응형 웹보다는 고정 프레임 안의 정렬 품질에 더 집중한다.

기본 원칙:

- 메인 콘텐츠는 한 화면 안에서 바로 읽히고 조작 가능해야 한다
- 사이드바와 본문 영역의 경계는 명확해야 한다
- 본문은 상단 헤더, 주요 콘텐츠, 하단 액션의 세 층으로 정리한다
- 같은 성격의 화면은 같은 레이아웃 골격을 재사용한다

권장 구조:

1. 좌측: 전역 네비게이션
2. 우측 상단: 현재 화면 제목, 짧은 보조 설명, 뒤로 가기
3. 우측 본문: 선택/입력/결과 중심 콘텐츠
4. 우측 하단 또는 본문 하단: 주요 액션 버튼

## 4. Visual System

### 4.1 Color

현재 전역 색 변수는 `src/index.css`에 있다. 새 색을 추가하기 전에 기존 토큰을 우선 사용한다.

기본 원칙:

- 배경은 밝고 중립적으로 유지
- 강조색은 기능별로 제한해서 사용
- 동일 화면에서 주조색은 1개, 보조색은 1~2개 수준으로 제한
- 경계선과 그림자는 약하게 유지

권장 역할:

- 기본 배경: `--color-canvas`, `--color-surface`
- 기본 텍스트: `--color-ink`
- 보조 텍스트: `--color-muted`
- 경계선: `--color-line`, `--color-line-strong`
- 기능 강조:
  - 훈련: 옅은 노랑/연두
  - 이력: 옅은 파랑
  - 내 정보: 옅은 코랄/피치

### 4.2 Typography

폰트 계열은 현재 `Pretendard` 중심이다. 새 폰트는 추가하지 않는다.

타이포 원칙:

- 페이지 제목은 크고 짧게
- 설명 문장은 1~2줄로 제한
- 카드 제목은 강하게, 보조 문구는 짧고 연하게
- 버튼 텍스트는 명령형으로 통일
- letter-spacing은 늘리지 않는다

권장 계층:

- Page title: 42~54px
- Section title: 28~36px
- Card title: 24~32px
- Body: 18~24px
- Caption/meta: 14~18px

## 5. Components

### 5.1 Sidebar

`Sidebar`는 전역 탐색 기준점이다.

규칙:

- 모든 주요 화면에서 같은 위치, 같은 폭 유지
- 활성 메뉴는 배경과 테두리 변화로만 구분
- 아이콘 스타일은 통일
- 메뉴 항목 높이와 간격은 모든 화면에서 고정

수정할 때 주의할 점:

- 항목 수가 늘어도 로그아웃 버튼과 충돌하지 않게 한다
- 각 메뉴의 색상 차이는 약하게 두고, 구조는 동일하게 유지한다

### 5.2 Header

`PageHeader`는 훈련 상세 화면의 공통 헤더다.

규칙:

- 뒤로 가기 버튼 위치 고정
- 제목과 부제는 최대 2줄 안에서 처리
- 화면마다 헤더 간격이 달라지지 않게 한다

### 5.3 Cards

훈련 선택, 이력 선택, 홈 카드 등은 모두 카드 계열 UI다.

규칙:

- 카드 내부 정렬 규칙을 통일한다
- 클릭 가능한 카드는 hover, focus, active 상태를 모두 가진다
- 카드 크기는 내용에 따라 흔들리지 않게 고정한다
- 카드 안에서 이미지, 제목, 설명, 액션의 순서를 유지한다

### 5.4 Buttons

규칙:

- 한 화면의 대표 액션은 1개만 가장 강하게 강조
- 보조 액션은 외곽선 또는 옅은 배경으로 처리
- 파괴적 액션은 현재 범위상 거의 없으므로 과한 빨강 사용 금지
- 비활성 상태는 충분히 구분되되 가독성은 유지

## 6. Page-by-Page Guidance

### 6.1 Intro / Signup

목표:

- 긴장감 없는 시작 흐름
- 단계 이동이 명확한 화면
- 입력보다 선택이 쉬운 구조

규칙:

- 한 화면에 핵심 선택 1개
- 이전/다음 흐름이 항상 보이게 유지
- 장식보다 진행 맥락이 먼저 보이게 구성

### 6.2 Login

목표:

- 재진입 사용자가 빠르게 시작

규칙:

- 입력 필드 2개와 CTA에 집중
- 보조 문구는 짧게 유지
- 경고/실패 메시지는 입력 영역과 가까운 곳에 표시

### 6.3 Main Page

목표:

- 훈련별 현재 상태를 즉시 파악
- 다음 행동이 자연스럽게 이어지도록 구성

규칙:

- 카드 3개는 동일한 구조 유지
- 성장 상태, 훈련 이름, 간단 설명의 우선순위 유지
- 홈은 정보 요약 화면이지 설명 화면이 아니다

### 6.4 Training

목표:

- 사용자가 지금 무엇을 해야 하는지 바로 알 수 있어야 함
- 사회성/안전/문서 훈련 간 UX 차이가 있어도 전체 앱 톤은 유지

규칙:

- 훈련 시작 전: 선택지를 큰 카드나 큰 버튼으로 단순화
- 훈련 진행 중: 현재 장면, 질문, 선택/행동 버튼을 강하게 구분
- 훈련 결과: 점수, 피드백, 다음 행동을 우선 배치
- 결과 화면에서 불필요한 텍스트는 줄이고 핵심 피드백만 남긴다

### 6.5 Training History

목표:

- 기록 목록에서 빠르게 비교
- 상세 화면에서 회고가 쉬운 구조

규칙:

- 목록은 날짜, 제목, 점수를 일관된 열 구조로 유지
- 선택 상태는 분명하게 표시
- 상세 화면은 기록, 피드백, 추천 응답의 3단 구조 유지

### 6.6 My Page

목표:

- 정보 확인과 수정이 혼동되지 않게 함

규칙:

- 조회 모드와 수정 모드는 분명히 분리
- 저장 버튼은 항상 예측 가능한 위치에 배치
- 편집 가능한 항목과 불가능한 항목을 시각적으로 구분

## 7. Code Rules For Design Work

디자인 수정 작업에서는 아래 원칙을 따른다.

- 새 화면을 만들기 전에 기존 공통 구조를 우선 재사용
- `TrainingPages.jsx`에 화면을 계속 추가하기보다, 수정 범위가 커지면 화면 단위 분리 고려
- 색상, 여백, 그림자 값은 가능한 한 토큰화
- 이미지 교체만으로 해결될 문제를 새 컴포넌트 추가로 풀지 않기
- 인라인 스타일보다 기존 CSS 파일 체계 우선 사용

특히 아래 패턴은 피한다.

- 한 화면만을 위한 공용 컴포넌트 추상화
- 같은 의미의 버튼 스타일을 파일마다 따로 정의
- 화면 수정 중 레거시 화면까지 같이 손대는 작업

## 8. Suggested Work Order

디자인 개편은 아래 순서로 진행하는 것이 안전하다.

1. 전역 톤 정리
   - `src/index.css`
   - `src/App.css`
   - `src/components/layout/Sidebar.css`
2. 진입 화면 정리
   - `src/components/intro/IntroStyles.css`
   - `src/pages/Login.css`
3. 홈 / 내 정보 정리
   - `src/pages/Mainpage.css`
   - `src/components/myPage/MyPageStyles.css`
4. 훈련 공통 셸 정리
   - `PageHeader`
   - 상태 블록
   - 카드 / 버튼 규칙
5. 훈련 세부 화면 정리
   - 선택 화면
   - 진행 화면
   - 결과 화면
   - 이력 화면

## 9. Definition Of Done

디자인 수정 완료 기준:

- 같은 종류의 화면끼리 시각 규칙이 일관됨
- 버튼, 카드, 헤더, 상태 메시지의 스타일 기준이 통일됨
- 텍스트가 넘치거나 겹치는 구간이 없음
- 훈련 흐름에서 사용자가 다음 행동을 즉시 이해할 수 있음
- 기존 mock 데이터 기준으로 주요 화면이 깨지지 않음

## 10. Immediate Recommendations

현재 프로젝트 기준으로 가장 먼저 할 만한 일:

1. `Sidebar`, `PageHeader`, 공통 버튼 스타일을 먼저 통일
2. 홈 / 훈련 선택 / 이력 선택 카드 디자인 규칙을 하나로 맞춤
3. `TrainingPages.css`의 공통 블록과 화면별 블록을 분리
4. 레거시 화면은 디자인 기준 문서에서 제외하고, 추후 삭제 후보로 관리
